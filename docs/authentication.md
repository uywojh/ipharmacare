# 患者账号认证方案

## MVP 流程

- 患者使用手机号与密码登录；注册和找回密码通过短信验证码验证手机号。
- 登录成功后由服务端创建随机、不透明的会话 ID；浏览器只通过 Secure、HttpOnly、SameSite=Lax Cookie 持有会话。
- 提供 `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/session` 和注册/重置密码接口。
- 会话有过期时间；退出、密码重置和账号停用时撤销相关会话。
- 登录错误使用统一提示；对验证码发送、密码尝试和账户恢复实施限流，避免枚举账号和暴力猜测。
- 服务端存储密码哈希（Argon2id 或经审核的 bcrypt），绝不保存或记录明文密码、验证码和会话令牌。
- 高风险操作重新验证身份；患者数据每次访问都执行资源级授权。照护者授权与患者登录身份分离。

## 数据模型建议

- `users`: ID、规范化手机号、密码哈希、状态、创建/更新时间。
- `sessions`: 哈希后的会话令牌、用户 ID、创建/过期/撤销时间。
- `verification_codes`: 手机号、验证码哈希、用途、过期时间、已使用状态和尝试次数。

手机号与健康数据属于敏感信息，应最小化采集、限制访问并加密备份。验证码通过外部短信服务发送，需在配置供应商、发送域名和防滥用策略后启用。

## 尚未启用的能力

当前仓库还没有数据库驱动、迁移、短信供应商、密码哈希实现和密钥管理配置。因此此文档是实现规格，不代表登录接口已经可用于真实患者或生产环境。开始接入前需选定部署地区、短信供应商、数据保留规则，并完成安全审查。
